# Проверки базовой прошивки FCPLCn

Текущая suite контроллеров содержит **46** сценариев, резервных копий — **37**.
Дополнительно проверяются три разных последовательных LOW, минимальные ON/OFF,
кэш точного последнего измерения до исходного срока 15 с, аварийный обход ON,
миграция FCCTRL05/06 и JSON v5/v6 в v7 с фиксированными 60 с. Временные сценарии используют виртуальные часы.

`test-base-runtime` проверяет политику независимого прогресса и переполнение времени.
`test-base-telemetry` проверяет восемь сценариев изменения/свежести/повтора и большой
OneWire-каталог; `test-base-static-cache` — выбор gzip/identity, ETag и версии ресурсов.
В FCCTRL07 индивидуальные таймеры исключены: 4486 из 5120 байт секции контроллеров
и 7464 из 7936 байт полного NVS-блоба для максимальной конфигурации.

`test-base-sockets` собирает настоящий C++ движок контроллеров и MQTT-парсер с fake NVS, типизированными I/O и временем. 46 сценариев под ASan/UBSan: сохранение и reboot модулей, HIGH→LOW, дребезг/удержание/отпускание, LOW при старте и восстановлении, эксклюзивные входы и реле, CAS/валидация, переназначение и удаление с OFF, выключение модуля, ошибки Flash/реле, ручное управление при отказе входа, конкурентное занятие порта, повреждённое хранилище, MQTT SET с независимыми sequence и защита от повторов/retained/expiry/другого bootId. «Метео» проверяется на сохранение настроек без перенастройки драйвера при отказе commit, общий OneWire-порт с разными ROM, запрет повторного ROM/смешивания типов, CRC адреса, выбранный ROM и устаревание данных, асинхронный поиск и смену DHT22→OneWire с проверкой владельца/ревизии. Термостаты проверяются без сетевого кода: точные пороги нагрева/охлаждения, общий источник для двух выходов, удержание в полосе, OFF при старте/отказе/устаревании/смене физического источника, неизменность NVS при работе, запрет ручного ON, переназначение/удаление, безопасный OFF при ошибке commit и hardware. Отдельные задержки в fake I/O проверяют истечение свежести во время ожидания наблюдения, перед OLAT и при неудачном rollback: запоздалого ON быть не должно. Индивидуальные выключатели проверяются на default OFF, сохранение после reboot без изменения config revision, HIGH→LOW с подавлением дребезга/удержания/LOW при старте, глобальные input claims, независимость от отказа необязательной кнопки, сохранение оперативного флага при правках формы, безопасный RAM inhibit после ошибки записи и восстановление только явной командой. MQTT термостатов проверяется на отдельную sequence, управление флагом без прямого ON реле, запрет повтора после локального OFF и истечение срока до записи NVS; срок команды не ограничивает дальнейшую автономную работу. Браузерный прогон также проверяет четыре плитки, формы, несохранённые правки, мобильную вёрстку, имитацию кнопки и дисковое сохранение. Занятые ресурсы видимы и недоступны с именем владельца; своё назначение и общий OneWire-порт доступны. Проверяются сохранённые и черновые назначения, выключенные модули, одновременные редакторы и выбранный порт, занятый другим редактором во время работы.

Проверка навигации охватывает вкладку «Сеть» с вложенными WiFi/Ethernet и отдельный «Хаб», независимые патчи `linux`/`time`, сохранение несохранённых полей при переходах и опросе, индикаторы изменений, клавиатуру и перенос меню на мобильном экране.

`test-base-backup` собирает реальные config/auth/socket/backup/settings_store с OpenSSL-адаптером PSA и fake NVS/I/O. 37 сценариев под ASan/UBSan: полный перенос между разными MAC, пароль и verifier, выходные состояния после reboot, strict profile/schema/module/port validation, commit failure без частичной замены, CAS, блокировка изменений после импорта, миграция legacy и отказ миграции, CRC fail-closed, ожидание незавершённых операций перед импортом, отказ каждой cJSON-аллокации без частичного сохранения, старые ID в бинарных настройках и JSON-копиях с сохранением ON-состояний. Проверяются JSON v7 с четырьмя модулями, v4 с миграцией прежних термостатов в enabled=true/inputId="", v3 с пустым выключенным «Термостатом», v2 с пустым выключенным «Метео», v1 с пустыми выключенными «Светом» и «Метео», конфликт ресурсов до любых изменений и загрузка старых FCSOCK01/FCCTRL02/FCCTRL03/FCCTRL04/FCCTRL05/FCCTRL06 без записи при старте. Старые общие входы сохраняются с приостановленной кнопочной автоматикой до исправления. Максимальная конфигурация 16 термостатов + 16 датчиков с предельными именами/ID занимает 4486 из 5120 байт секции контроллеров; весь комплект с максимально экранируемыми строками настроек — 7464 из 7936 байт NVS-блоба. Разметка Flash не менялась. Перенос термостата сохраняет настройки, вход кнопки, подтверждённый индивидуальный ON/OFF и ссылку на источник, включая удалённый источник, но не автоматическое состояние реле; после reboot нужен достоверный локальный датчик. Pending restore проверяется на безопасный OFF термостатов без дополнительного commit и без изменения уже подготовленного комплекта. Старые модульные suites используют отдельный fake settings_store поверх прежних fakeNVS; общий production store проверяется именно здесь. Браузер дополнительно проверяет скачивание saved-only JSON, выбор/просмотр/загрузку файла, второй PLC, кириллицу по частям HTTP и автоматическую перезагрузку.

`test-base-hardware-io` проверяет настоящий драйвер MCP23017 в 18 сценариях ASan/UBSan. В fake воспроизводятся BANK/SEQOP и обе карты регистров, полный сброс, дрейф каждого класса настроек, GPIO/OLAT mismatch, повреждённое чтение, проигнорированная запись и потеря ACK. Проверяется восстановление буфера 16 выходов, отзыв ON при OFF даже во время NACK, отсутствие отложенного failed/expired ON, проверка профиля до восстановления уровней, Controller OFF после fault/stale, новые поколения входов и независимость двух MCP. Отдельно проверяется, что hardware JSON не выдаёт кэш старше 300 мс как достоверные уровни. Core и backup suites дополнительно проверяют регистрацию политик: init, OFF→commit→смена владельца, отсутствие смены после failed commit, применение импортированных привязок только после reboot.

`test-base-meteo` собирает настоящий сенсорный worker и DS18B20 codec с fake GPIO/RMT/DHT и монотонным временем. 10 сценариев под ASan/UBSan: CRC/ROM и отрицательные температуры/разрешение DS18B20, несколько датчиков на шине, DHT22 и диапазоны показаний, поиск при выключенном модуле без синхронного I/O в HTTP-вызове, ошибка CRC и выделения RMT с восстановлением, тайм-аут преобразования без ложных 85 °C, устаревание, смена привязки во время преобразования, отказ паразитного питания и обслуживание нескольких портов одной парой RMT. Браузер проверяет отдельный список ROM, доступность общих OneWire-портов, занятый ROM серым, сохранение отсутствующего ROM и первоначальный поиск даже при открытии страницы до первого ответа API. Физические датчики и электрические задержки изолятора на плате этими проверками не заменяются.

`test-base-config` собирает реальные `main/config/model.cpp`, `main/config/config.cpp`, `main/hardware/board_profile.cpp` и исходный managed-компонент cJSON. ESP MAC, журнал и NVS заменены небольшими платформенными заглушками. В NVS можно имитировать ошибку commit. Проверяются настройки по умолчанию, аппаратный профиль в публичной и сохранённой конфигурации, загрузка старой NVS без профиля, отказ для неизвестного профиля без записи, UTF-8 SSID, сетевые ограничения, пароли и публичный JSON, ревизии, сохранение, восстановление и защита входного JSON от NUL и чрезмерной вложенности. Старые записи получают текущий профиль в памяти и сохраняют его при следующем изменении настроек. Ошибка записи проверяет сохранение активной конфигурации в коде приложения; физическое поведение Flash при пропадании питания требует отдельной проверки на плате.

Для native-сборки нужен скачанный managed-компонент `firmware/base/managed_components/espressif__cjson`. Он появляется при конфигурировании основной ESP-IDF сборки. Другой каталог можно передать как `tools/firmware/test-base-config -DFCPLCN_CJSON_DIR=/absolute/path/to/cJSON`.

`test-base-hardware-io` компилирует аппаратный ввод-вывод, безопасный старт GPIO и профиль с I²C/GPIO/FreeRTOS-адаптером. Проверяются стартовые уровни на обеих платах, кнопка восстановления, порядок OLAT до IODIR, карты MCP, уровни входов, изоляция отказов расширителей, ошибки записи/подтверждения, восстановление OFF, сканирование и конкурентный доступ к шине. `test-base-rtc` компилирует драйвер DS3231, календарный кодек и сервис RTC. Он проверяет календарь 2000–2099, BCD, 12/24 часа, OSF, ошибки и устаревшие данные, запись с подтверждением и конкурентный доступ. Оба стенда запускаются с ASan/UBSan. Сборки располагаются в `~/esp/build/fcplcn/`.

`test-base-ui` запускает Chromium, настоящий `web/index.html`, `app.js` и `style.css` с локальным HTTP mock API. Используются уже установленные Playwright и Chromium из среды `tools/firmware/web-smoke`; новые зависимости не устанавливаются. Тест проверяет вход, настройки, polling с несохранёнными полями, выбор профиля, смену учётных данных, ошибки интерфейсов, время, перезагрузку и мобильную вёрстку. Аппаратная вкладка проверяется на переключение реле только после подтверждения, HIGH/LOW/неизвестные входы, ошибки связи и записи, RTC, обе I²C-шины, последовательные GET/POST и выключение реле при виртуальном перезапуске. Заголовок CSP разрешает только собственные ресурсы.

Mock API проверяет браузерный контракт, а не драйверы ESP32 и не производственную авторизацию. Сервер привязывается к свободному порту `127.0.0.1` и завершается вместе с браузером. Скриншоты сохраняются в игнорируемый каталог `browser/.artifacts/`; native-сборка — в `.build/`.
