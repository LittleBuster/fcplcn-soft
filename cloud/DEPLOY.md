# Облако FCPLCn на своём VPS

В составе развёртывания: **FCPLCn — Future City PLC Next**, PostgreSQL 18.7,
Mosquitto 2.0.23 с индивидуальными правами каждого хаба и Caddy 2.11.9 для HTTPS.
Серверное приложение работает от отдельного пользователя в Node.js 24.22.3.
На VPS нужны Docker Engine с Compose **2.24.4 или новее**, доменное имя и доступные
порты **80/TCP, 443/TCP, 443/UDP и 8883/TCP**. База данных и порт приложения 4100
наружу не публикуются. Направьте DNS A/AAAA домена на VPS; оставляйте AAAA только
при работающем IPv6.

## Первоначальный запуск

Для автоматической установки из корня `fcplcn-soft` выполните команду:

```sh
./install.sh cloud --domain cloud.example.com
```

Автоматическая и ручная установки используют свои каталоги runtime.
Подробности о скриптах описаны в [инструкции развёртывания](../deploy/README.md).
Ниже приведён ручной вариант с Compose.

Все команды выполняются из корня репозитория. Вместо `cloud.example.com`
подставьте свой домен:

```sh
cloud/deploy/setup.sh cloud.example.com
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml up -d --build
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml ps
```

Установка не требует Node.js или OpenSSL на VPS: отдельный подготовительный
контейнер создаёт случайные пароли, ключ первоначальной настройки и сертификат
облачного брокера. Они не выводятся в журнал. Каталог `cloud/deploy/runtime`
закрыт правами `0700`, файл `.env` — `0600`. В нём находятся домен и имя проекта;
сами секреты хранятся в закрытых каталогах отдельного Docker volume.

Caddy автоматически получает публичный HTTPS-сертификат. Откройте
`https://cloud.example.com`. На новой установке войдите с логином **`admin`**,
поле пароля оставьте пустым. В настройках учётной записи можно изменить логин
и пароль. При последующих запусках и обновлениях изменённые данные сохраняются;
в существующей базе аккаунты не заменяются и их пароли не сбрасываются.
Пользователей приглашает владелец дома через веб-панель. Старые аккаунты с адресом
почты в качестве логина продолжают работать; SMTP и отправка писем не требуются.

Создайте дом, выпустите код подключения хаба. В локальной панели хаба откройте
**Облако**, введите HTTPS-адрес этого сервера и код. Хаб получает собственные
отзываемые учётные данные и CA брокера через этот проверенный HTTPS-канал.
Подключение к брокеру выполняется с проверкой имени и сертификата TLS.
PLC продолжают использовать только локальный MQTT-брокер.

## Хранение и права

По умолчанию имя проекта — `fcplcn-cloud`. Постоянные volumes:

| Volume                                                  | Содержимое                                                                                                 |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `fcplcn-cloud_private`                                  | Ключ шифрования приложения, начальный ключ, отдельные пароли PostgreSQL и облачного MQTT, закрытый ключ CA |
| `fcplcn-cloud_broker`                                   | Сертификат брокера, его ключ и `dynamic-security.json` со всеми подключёнными хабами                       |
| `fcplcn-cloud_cloud`                                    | Временные файлы прошивок и данные приложения                                                               |
| `fcplcn-cloud_database`                                 | PostgreSQL: пользователи, дома, права, журнал и подключения                                                |
| `fcplcn-cloud_caddy-data` и `fcplcn-cloud_caddy-config` | HTTPS-сертификаты Caddy и его состояние                                                                    |

В приложении используется роль PostgreSQL `fcplcn_app` без прав суперпользователя,
создания ролей и других баз. Пароль `postgres` другой. Закрытые каталоги volume
разделены по UID: приложение **1000**, PostgreSQL **70**, брокер **1883**. Файлы
секретов имеют права `0600`; каталог корня private volume разрешает проход к
своему каталогу, но не просмотр остальных.

Изначально в брокере существует только облачная служебная учётная запись.
У неё доступны управление динамическими правами и адресованные облачные темы.
Для каждого хаба приложение создаёт отдельную роль с буквальными темами только
этого хаба и привязкой MQTT client ID. Все четыре разрешения брокера по умолчанию
запрещены. Брокер не подключается к LAN-брокерам, не сохраняет retained-сообщения
и не восстанавливает старые команды после перезапуска.

## Повторная подготовка, обновление и сертификаты

Облако, установленное через `install.sh`, обновляйте отдельным скриптом:

```sh
./update.sh cloud
```

Скрипт обновляет приложение, PostgreSQL, Mosquitto и Caddy. Настройки и базы
остаются в существующих томах. Перед перезапуском создаётся резервная копия.

Для ручного развёртывания повторная подготовка выполняется так:

```sh
cloud/deploy/setup.sh cloud.example.com
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml up -d --build
```

Повторная подготовка сохраняет пароли, ключ CA, пользователей брокера, подключения
хабов и базу. Другой домен или имя проекта для уже созданных данных отклоняются.
Закрытые ключи не меняются вследствие обычной пересборки приложения.

Сертификат брокера выдаётся на год. Подготовка обновляет его, когда осталось
меньше 30 дней; CA сохраняется, поэтому повторное подключение хабов не нужно.
Запускайте подготовку ежемесячно и затем перезапускайте брокер для чтения
сертификата. Для досрочного перевыпуска:

```sh
cloud/deploy/setup.sh cloud.example.com --renew-cert
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml restart broker
```

CA рассчитан на десять лет. Его замена выполняется отдельным переносом доверия;
установка сообщает о приближении срока, не подменяя CA автоматически.
Публичные HTTPS-сертификаты Caddy продлеваются автоматически.

Для другого независимого экземпляра задайте `FCPLCN_PROJECT` и
`FCPLCN_RUNTIME_DIR` при каждом вызове подготовки. Порты должны быть свободны.
В командах Compose используйте созданный в выбранном каталоге `.env`.

## Резервная копия

Нужны **и база данных, и private volume**. Без прежнего ключа приложения нельзя
расшифровать сохранённые секреты двухфакторной аутентификации; без broker volume
потеряются индивидуальные подключения хабов. Не пересоздавайте ключи при
восстановлении базы.

Пример логической копии базы, без вывода паролей:

```sh
umask 077
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml exec -T db pg_dump -U postgres fcplcn > fcplcn.sql
```

Для согласованной физической полной копии остановите все службы, включая
PostgreSQL, сохраните volumes, private volume и данные Caddy средствами
резервного копирования Docker, затем запустите службы. Файлы PostgreSQL нельзя
архивировать на работающей базе. Для управляемой установки полную копию создаёт
`./deploy/manage.sh cloud backup`. Храните копии закрыто. Команда `docker compose down`
сохраняет volumes; не добавляйте `--volumes` при обычном обновлении.

## Локальная проверка без публикации

Отдельное переопределение отключает Caddy и публикует только loopback-порты
**4100** и **18883**. Оно предназначено для разработки на этом компьютере:

```sh
cloud/deploy/setup.sh cloud.example.com
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml -f cloud/deploy/compose.local.yaml up -d --build
```

Панель: `http://127.0.0.1:4100`. MQTT остаётся TLS, сертификат содержит
`127.0.0.1`, `localhost` и внутреннее имя `broker`. Только для подключения
локального тестового хаба к HTTP-панели разрешите у него
`FCPLCN_CLOUD_ALLOW_INSECURE_LOOPBACK=1`. Рабочий HTTPS-вариант этого не требует.
Локальный вариант не используется для подключения других компьютеров.

Проверка конфигурации без запуска:

```sh
docker compose --env-file cloud/deploy/runtime/.env -f cloud/deploy/compose.yaml config --quiet
```

Локальный стенд из `~/esp/build/fcplcn/cloud-dev/` — отдельное окружение разработчика;
подготовка production volumes его не читает и не изменяет.
