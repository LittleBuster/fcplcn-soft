# FCPLCn Cloud

Облачная панель **FCPLCn — Future City PLC Next** для собственного сервера/VPS.
Сервер написан на TypeScript для Node.js 24, интерфейс — на TypeScript/Preact,
пользователи, дома и права хранятся в PostgreSQL. Облако использует общий интерфейс
хаба и сервисную панель PLC, поэтому локальные и удалённые настройки совпадают.

## Установка на сервер

Из корня `fcplcn-soft` на Debian 13 amd64/arm64:

```sh
./install.sh
```

Выберите **1 — cloud**, затем **1 — Установка** или **2 — Обновление**.
При первой установке укажите свой домен в запросе установщика.

Установщик подготовит Docker и Compose, PostgreSQL, MQTT/TLS, приложение и Caddy.
Обновление сохраняет пользователей, дома, подключения и ключи, создаёт полную
копию и проверяет готовность служб. Публикация образов из GitHub, откат и
восстановление описаны в [deploy/README.md](../deploy/README.md).

## Что реализовано

- Вход по логину и паролю: на новой установке `admin` с пустым паролем. Логин и
  пароль меняются в настройках учётной записи; доступны TOTP и коды восстановления.
- Несколько домов, приглашения по ссылке, роли пользователей, отдельное разрешение
  управления охраной и отзыв подключения хаба.
- Состояния PLC, розеток, света, метео, термостатов и охраны; подтверждённые команды.
- Сценарии «Я дома», «Ушел», «Готовлюсь», собственные действия и недельные расписания.
  Три крупные быстрые плитки показаны только на главном обзоре хаба.
- Полная настройка PLC: добавление/удаление элементов, назначение портов, поиск
  OneWire/iButton, сеть, профиль платы, часы, пользователь и резервная копия JSON.
- Загрузка бинарника приложения через HTTPS с последующей установкой выбранному
  PLC через хаб; доступны прогресс и проверка запуска нового образа.
- Журнал удалённых действий, отдельные признаки отсутствия связи и давности данных,
  тёмный адаптивный интерфейс с SVG.

SMTP не требуется: приглашение владелец передаёт сам. Существующие учётные записи
с адресом почты в качестве логина сохраняют доступ. Автоматическая покупка домена,
аренда VPS и публикация сервера не выполняются.
Для доступа из интернета нужны ваш домен, сервер и его действующий HTTPS-адрес.

## Как проходит управление

```text
Браузер пользователя ── HTTPS ── Облачный API + PostgreSQL
                                      ↕
                            Облачный MQTT-брокер TLS
                                      ↕ исходящее соединение хаба
                              Linux-хаб в домашней LAN
                                      ↕
                              Локальный MQTT-брокер
                                      ↕
                              Автономные PLC на C++
```

Только Linux-хаб получает облачные полномочия и открывает исходящие соединения к
серверу. Входящие порты домашнего роутера и прямой доступ облака к PLC не нужны.
Облачный и локальный брокеры раздельны; общей пересылки всех MQTT-тем нет.
Запрос проверяется облачным API и хабом, затем проходит штатные проверки PLC.
Успех появляется после подтверждения устройства, а не после приёма запроса брокером.

Для каждого хаба создаётся отдельная отзываемая учётная запись облачного брокера
с доступом только к его темам. Проверяются TLS-сертификат и имя сервера. Команды
ограничены текущим соединением, последовательностью и сроком исполнения, не имеют
retain и не повторяются автоматически после переподключения. Потеря ответа может
означать неизвестный результат; перед повторным действием нужно проверить состояние.

При потере интернета локальные сценарии, расписания, веб-панель и MQTT хаба
продолжают работу. При остановке самого хаба PLC сохраняют свои настройки и
автономные функции, включая термоконтроль. Облачная страница показывает последние
сведения как устаревшие и не отправляет команды в очередь до возвращения связи.

## Развёртывание и локальный просмотр

Проверенная схема Docker Compose, подготовка закрытых ключей, HTTPS, резервные
копии и обновление сертификатов описаны в [DEPLOY.md](DEPLOY.md).
В неё входят PostgreSQL, Mosquitto с dynamic-security, приложение и Caddy.
Для просмотра на этом компьютере предусмотрен отдельный loopback-вариант Compose:
он открывает панель на `http://127.0.0.1:4100` и не публикует её в интернете.

## Сборка из исходников

Нужен **Node.js 24.x**. Из корня репозитория:

```sh
npm --prefix hub ci
npm --prefix cloud ci
npm --prefix hub run build
npm --prefix cloud run build
```

Сначала собирается хаб: его готовые веб-ресурсы и панель PLC включаются в облачный
пакет. Результат облачной сборки находится в `cloud/dist/`: сервер —
`cloud/server/`, основной интерфейс — `web/`, общие интерфейсы — `portal/` и `plc/`.
Метаданные продукта берутся из `config/product.json`.

Для запуска из исходников уже должны работать PostgreSQL и облачный Mosquitto с
TLS и плагином dynamic-security. Служебная MQTT-учётная запись должна иметь права
управления индивидуальными подключениями хабов; произвольного публичного брокера
для этого недостаточно. Готовую конфигурацию предоставляет развёртывание выше.

Создайте закрытый `cloud/.env`, задайте параметры из таблицы ниже и запустите:

```sh
cd cloud
chmod 600 .env
npm start
```

Миграции PostgreSQL выполняются при запуске. Сервис слушает `127.0.0.1:4100` по
умолчанию. Для публичной установки HTTPS завершается на обратном прокси; его адрес
должен совпадать с `FCPLCN_CLOUD_PUBLIC_ORIGIN`. Установка и запуск не требуют
переносить исходники или облачные ключи на PLC.

## Настройки сервера

Параметры загружает `server/config.ts`. Значения с секретами можно передавать
через переменную с окончанием `_FILE`: её значение — путь к закрытому файлу,
содержимое которого заменяет обычную переменную.

| Переменная                             | По умолчанию / требование                               | Назначение                                                                                                |
| -------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `FCPLCN_CLOUD_HOST`                    | `127.0.0.1`                                             | Адрес HTTP-сервера за прокси                                                                              |
| `FCPLCN_CLOUD_PORT`                    | `4100`                                                  | Порт приложения                                                                                           |
| `FCPLCN_CLOUD_PUBLIC_ORIGIN`           | `http://127.0.0.1:4100`                                 | Корневой публичный HTTPS-адрес; HTTP разрешён только для loopback                                         |
| `FCPLCN_CLOUD_DATABASE_URL`            | Обязателен; поддерживает `_FILE`                        | URL PostgreSQL служебного пользователя приложения                                                         |
| `FCPLCN_CLOUD_DATA_DIR`                | `./data` относительно каталога запуска                  | Закрытые ключи приложения и временные бинарники                                                           |
| `FCPLCN_CLOUD_SETUP_KEY`               | Создаётся в `DATA_DIR/setup.key`; поддерживает `_FILE`  | Ключ совместимости прежнего API первичной настройки, 24–256 символов; обычному входу `admin` не требуется |
| `FCPLCN_CLOUD_MASTER_KEY`              | Создаётся в `DATA_DIR/master.key`; поддерживает `_FILE` | 32 случайных байта в hex/base64 для шифрования секретов TOTP                                              |
| `FCPLCN_CLOUD_MQTT_URL`                | `mqtts://127.0.0.1:8883`                                | Адрес облачного брокера, доступный приложению                                                             |
| `FCPLCN_CLOUD_MQTT_USERNAME`           | Обязателен; поддерживает `_FILE`                        | Служебный пользователь облачного брокера                                                                  |
| `FCPLCN_CLOUD_MQTT_PASSWORD`           | Обязателен; поддерживает `_FILE`                        | Его пароль                                                                                                |
| `FCPLCN_CLOUD_MQTT_CA`                 | Системное доверие; поддерживает `_FILE`                 | CA облачного брокера: PEM или путь к файлу                                                                |
| `FCPLCN_CLOUD_PUBLIC_MQTT_URL`         | Значение `MQTT_URL`                                     | TLS-адрес брокера, доступный домашним хабам; в Docker обычно отличается от внутреннего                    |
| `FCPLCN_CLOUD_PUBLIC_MQTT_CA`          | Системное доверие; поддерживает `_FILE`                 | CA, передаваемый хабу при HTTPS-привязке: PEM или путь                                                    |
| `FCPLCN_CLOUD_ALLOW_INSECURE_LOOPBACK` | Выключено                                               | `1` разрешает тестовый MQTT без TLS только на loopback при локальном `PUBLIC_ORIGIN`                      |

Имена файлов для `_FILE`, пароли и ключи не следует помещать в публичные журналы.
Сохранение базы без прежнего `MASTER_KEY` не позволяет восстановить секреты TOTP.
Процедура согласованной резервной копии всех volumes приведена в [DEPLOY.md](DEPLOY.md).

## Пользователи, привязка и права

1. Откройте панель и войдите: логин `admin`, пароль оставьте пустым. На новой
   установке эта учётная запись создаётся автоматически. В настройках своей
   учётной записи можно задать другой логин и пароль. Перезапуск и обновление
   приложения сохраняют изменённые данные; существующие аккаунты не сбрасываются.
2. Создайте дом. Во вкладке **Подключение** получите одноразовый код привязки.
3. В локальной панели хаба откройте **Облако** и введите HTTPS-адрес облачной панели,
   код и имя хаба. По умолчанию облако на хабе выключено.
4. Дождитесь состояния **На связи**. На один дом привязывается один активный хаб;
   для замены сначала отзовите прежнее подключение в облачной панели.
5. Во вкладке **Пользователи** создайте приглашения и передайте ссылки людям.
   Ссылки ограничены сроком; при необходимости можно задать конкретную почту.

| Роль         | Доступ                                                                 |
| ------------ | ---------------------------------------------------------------------- |
| Владелец     | Настройки дома и PLC, пользователи, привязка, сценарии, Telegram и OTA |
| Пользователь | Просмотр, включение/выключение оборудования и запуск сценариев         |
| Наблюдатель  | Просмотр состояний и сценариев без управления                          |

Для роли «Пользователь» управление охраной выдаётся отдельным разрешением. Оно
проверяется и для сценариев, содержащих постановку/снятие охраны. Права проверяются
сервером и хабом, скрытие кнопок служит только удобством интерфейса.

В настройках своей учётной записи можно включить TOTP: подтвердить текущий пароль,
добавить показанный секрет в приложение аутентификации и ввести проверочный код.
Полученные коды восстановления нужно сохранить отдельно; каждый используется
один раз. Для отключения TOTP требуются пароль и код. Облачная учётная запись,
локальный администратор хаба и пользователь PLC — разные учётные записи.

### Картинки PLC

На странице выбранного PLC владелец может нажать **Картинка**, найти изображение
в каталоге из 30 SVG и нажать **Сохранить картинку**. Например, для гаражного PLC
можно выбрать гараж, а для отопления — котельную. Изображение видно на общей
карточке и странице устройства как в облаке, так и в локальном хабе.
Выбор сохраняется на хабе вместе с именем и помещением; переименование его не
сбрасывает. Пользователи и наблюдатели видят картинку, но не меняют её.

### Общая охрана и iButton

Таблетка, разрешённая на одном из PLC, переключает общий режим «Я дома»/«Ушел»
через локальный хаб. Охрана остальных известных PLC согласуется автоматически;
ручного списка целевых устройств нет. Настроенные действия сценария, включая
контакторы, запускаются сразу и не ждут отсутствующие PLC. Когда устройство
возвращается, оно получает текущий режим охраны без повторного выполнения старых
действий. Облачная панель показывает заданный режим отдельно от подтверждений.
Удержание таблетки и повтор одного события не создают новые запуски.
Принятый режим и фактическая фаза различаются: задержки постановки/снятия видны
отдельно, тревога выделена красным. Контакторы не ждут окончания задержки на выход.

В демонстрации касание можно воспроизвести кнопкой **Приложить таблетку** на
странице PLC с охраной. Доступ имеют владелец и пользователь с отдельным правом
управления охраной. Наблюдатель видит статус и не может выполнить касание.

## Обновление приложения PLC из облака

Владелец открывает **Прошивка PLC**, выбирает бинарник приложения `FCPLCn.bin`,
затем целевой PLC и явно запускает установку. Объединённый `FCPLCn-full.bin`,
загрузчик и образы другого проекта или чипа отклоняются.

1. Браузер загружает файл в закрытое временное хранилище облака по HTTPS.
2. Хаб получает краткоживущее одноразовое разрешение и сам скачивает файл по HTTPS.
   URL не задаётся пользователем: используется адрес привязанного облака.
3. Хаб проверяет размер, SHA-256 и структуру приложения ESP32-S3, затем передаёт
   последовательные блоки по локальному частному MQTT-сервису PLC.
4. PLC повторяет проверку и записывает неактивный OTA-раздел. После активации хаб
   подтверждает идентификатор образа и новый загрузочный раздел.

Один файл ограничен 6 МиБ, хранится до часа; действуют ограничения количества и
общего объёма временных файлов. Разрешение на скачивание действует две минуты и
привязано к конкретному хабу. Временный файл на хабе удаляется после завершения;
прерванная передача не возобновляется после перезапуска.

Хаб приостанавливает ручное управление и запуск сценариев на время установки.
Локальные циклы PLC продолжаются до его перезагрузки, затем проходят штатный
безопасный запуск. Настройки NVS, FRAM и аппаратный профиль не стираются.
Обрыв соединения не приводит к повторной установке; если активация могла пройти,
а новый запуск не подтверждён, показывается неизвестный результат.

SHA-256 проверяет целостность. Подпись издателя релиза и Secure Boot этим не
реализуются. У старого PLC без OTA-сервиса сначала требуется обновление через USB.
Также сохранена загрузка через **Настроить PLC → Система** и локальную панель PLC.

## Проверки

Исходники облачного интерфейса находятся в `web/`:

```text
web/src/
  main.tsx       запуск Preact
  app/           сборка приложения и контракты между его частями
  pages/         вход, учётная запись, доступ, подключение, управление и журнал
  components/    верхняя панель, навигация, участники, формы и уведомления
  hooks/         сессия, данные дома, черновики, действия, история и iframe
  lib/           небольшие функции представления
  styles/        общие элементы, страницы и адаптивная компоновка
```

Оболочка соединяет страницы и хуки; общие черновики подключения, приглашений и
создания дома остаются в оболочке при переходе между разделами.
Управление PLC использует общую панель хаба,
а обновление прошивки остаётся отдельным модулем `firmware.tsx`.
Порядок CSS-импортов сохраняет существующий каскад.

Интерфейс использует тот же Prettier
**3.10.1** и правила из корня проекта, что и веб хаба: два пробела, строки до
100 символов, одинарные кавычки TypeScript и точки с запятой. JSDoc описывает
компоненты и существенные условия работы с сессиями, правами и обновлениями;
состояния компонентов и CSS-разделы сгруппированы по назначению.

```sh
npm --prefix cloud run format:web        # Применить оформление только к вебу облака.
npm --prefix cloud run format:web:check  # Проверить без изменения файлов.
```

Оба интерфейса: `node tools/web/format-code.mjs --check` из корня проекта.
Команда требует Node.js 24 и установленного форматтера из
`tools/firmware/code-style`; сборки и рабочие данные она не затрагивает.

```sh
npm --prefix cloud run typecheck
npm --prefix cloud test
npm --prefix cloud run test:browser
```

Для отдельной проверки общего iButton и облачных разрешений:

```sh
FCPLCN_CLOUD_BROWSER_SECURITY_ONLY=1 npm --prefix cloud run test:browser
```

Используется изолированный виртуальный дом: касания проходят реальный HTTP/API,
координатор хаба и модель PLC; отдельная маска отключает один PLC для проверки
возвращения. Удержание воспроизводится отсчётами считывателя, повторная доставка
проверяется отдельно. Конфигурации рабочего хаба не затрагиваются.

Проверки с PostgreSQL используют `FCPLCN_CLOUD_TEST_DATABASE_URL`, указывающий на
отдельную тестовую базу. В ней создаются и удаляются изолированные схемы; рабочую
базу для тестов использовать не следует. Браузерные проверки требуют установленного
Chromium Playwright и предварительно собранных хаба и облака. Они проверяют реальный
HTTP/API, PostgreSQL, учётные записи, TOTP, приглашения и права, общие панели и мобильную
вёрстку; PLC при этом виртуальные. Интеграция TLS MQTT и проверки файлов выполняются
отдельно. Прошивка физических контроллеров и развёртывание публичного VPS этими
проверками не выполняются.
