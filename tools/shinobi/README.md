# Установка Shinobi

Автономный `install.sh` для Debian 12/13 и Ubuntu 22.04/24.04/26.04/26.10, amd64/arm64, systemd. Скопируйте **один файл** на Linux-компьютер регистратора, подключите внешний USB-диск и запустите:

```bash
sudo bash install.sh
```

Установщик показывает внешние разделы, спрашивает номер раздела, порт и логин. Он не форматирует диск. Поддерживаются существующие ext4, xfs, btrfs, exFAT и NTFS; для NTFS устанавливается ntfs-3g. Зашифрованные и неразмеченные диски сначала нужно подготовить отдельно. Для нового диска под постоянную запись предпочтителен ext4.

Выбранный раздел монтируется по UUID в `/srv/shinobi-disk` отдельной службой systemd; запись идёт в `recordings/` этого раздела. Уже имеющиеся файлы сохраняются. При пропаже диска регистратор останавливается; при отсутствии/подмене UUID не запускается. Контейнеры не имеют отдельного автозапуска Docker и поэтому не стартуют до проверки диска. После повторного подключения: `sudo systemctl start fcplcn-shinobi`. Изменения `/etc/fstab` не требуются.

Настройки и база хранятся на системном диске в `/opt/fcplcn-shinobi`. Используются официальный ShinobiDocker **v2** и отдельная MariaDB 11.4, с закреплением скачанных digest. Повторный запуск не обновляет образы и не сбрасывает учётные записи или конфигурацию. Обновление/миграция уже существующей сторонней установки не выполняются.

После установки откройте `http://IP_КОМПЬЮТЕРА:8080` (либо выбранный порт). Доступные IP можно посмотреть командой `hostname -I`. Первоначальные пароли обычной учётной записи и отдельного суперпользователя хранятся с доступом только root:

```bash
sudo cat /opt/fcplcn-shinobi/access.json
```

Суперпользователь входит по `/super`. Пароли генерируются случайно. Временный ключ создания пользователя удаляется после настройки. Файл хранит именно первоначальные пароли: изменение пароля в интерфейсе его не обновляет.

Первой учётной записи выделяется 80% доступного при установке места внешнего раздела и срок хранения 30 дней. При достижении лимитов старые записи удаляет сам Shinobi. Эти параметры можно изменить в интерфейсе. Это не гарантия 30 дней архива: фактическая глубина зависит от битрейта и числа камер. Каталог `recordings` используется установщиком для Shinobi; не кладите туда посторонние файлы.

Камеры добавляются в **ONVIF Scanner** по диапазону IP, логину и паролю камеры. Автоматически подобрать пароли и универсальные параметры записи для всех камер установщик не может. Docker использует обычную изолированную сеть: сканирование адресов и соединения с камерами доступны, широковещательный WS-Discovery через мост не гарантируется. Для начала удобно H.264; воспроизведение H.265 зависит от телефона/браузера.

## Управление

```bash
sudo systemctl status fcplcn-shinobi
sudo journalctl -u fcplcn-shinobi -n 100
sudo systemctl restart fcplcn-shinobi
sudo systemctl stop fcplcn-shinobi
sudo bash /opt/fcplcn-shinobi/install.sh
```

Перенос/резервная копия: остановите `fcplcn-shinobi`, сохраните `/opt/fcplcn-shinobi` и `/srv/shinobi-disk/recordings`, затем снова запустите службу. Копировать живой каталог MariaDB как обычные файлы нельзя.

## Доступ с телефона

В домашней сети используется тот же локальный адрес. Для доступа из интернета выбран отдельный VPS с HTTPS и обратным туннелем Xray через VLESS + REALITY к Linux-регистратору. Linux-компьютер инициирует соединение к VPS, а VPS передаёт через него запросы браузера к Shinobi — обычного исходящего VLESS-прокси для этого недостаточно. Телефону нужен только браузер: участок телефон → VPS использует обычный HTTPS. Записи остаются на USB-диске; VPS передаёт просмотр и управление. Это подходит для серого IP. PLC к VPS не подключаются. Работа локального регистратора и автоматики не зависит от доступности VPS. В будущем конфигурация туннеля должна разрешать доступ только к локальному порту Shinobi. VLESS + REALITY не гарантирует доступность при блокировке адреса VPS.

Домен необязателен: Let's Encrypt поддерживает публичные IP-сертификаты с коротким сроком действия и автоматическим обновлением. Конкретная настройка VPS зависит от его ОС, IP и уже занятых портов. **Этот install.sh пока устанавливает локальный регистратор; VPS и VPN он не настраивает.** HTTP-порт локального регистратора не следует пробрасывать напрямую в интернет. Установщик не меняет правила firewall и проброс портов роутера.

## Проверки и источники

```bash
python3 tools/shinobi/build_installer.py --check
bash -n tools/shinobi/install.sh
python3 -m unittest discover -s tools/shinobi/tests -v
```

Проверены генерация, разбор Compose и сценарии выбора/проверки диска, зависимость службы от монтирования, создание пользователя без повторного сброса и удаление временного ключа. Полная установка с реальным USB-диском на целевом Debian/Ubuntu здесь не выполнялась.
