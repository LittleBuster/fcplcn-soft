# VLESS: Россия → Россия / Армения

Два автономных установщика для чистого **Debian 13 с systemd**. На каждый VPS копируется только соответствующий `install_*.sh`; дополнительные файлы из этого каталога не нужны. Пользователи создаются в России, Армения принимает их зарубежный трафик через один служебный UUID.

## 1. Сначала Армения

Войдите на армянский VPS как root и запустите:

```bash
bash install_arm.sh
```

Скрипт спросит публичный IPv4 этого VPS, входящий TCP-порт (по умолчанию `443`), SNI/target REALITY (по умолчанию `www.microsoft.com`) и публичный IPv4 российского VPS. SNI должен быть доступным сайтом с TLS 1.3; доступность проверяется. Генерируются ключи, Short ID и один служебный пользователь `ru-uplink`.

В конце выводится `vless://`-ссылка. Сохраните её: она понадобится в России. Копия лежит в `/opt/vless-arm/clients/ru-uplink.txt`, соответствующий клиентский Xray JSON — в `ru-uplink.json`. Повторный запуск использует прежние ключи и UUID, повторно применяет конфигурацию и печатает тот же профиль; Xray кратковременно перезапускается.

Откройте выбранный **TCP-порт Армении только с IPv4 российского VPS** в firewall провайдера. Скрипт также ограничивает источник для авторизованного проксируемого трафика внутри Xray. Правила firewall установщик не меняет.

## 2. Затем Россия

На российском VPS под root:

```bash
bash install_ru.sh
```

После проверки зависимостей открывается меню:

| Пункт | Действие |
|---|---|
| `1` | Установить узел либо восстановить запуск с сохранёнными настройками |
| `2` | Создать нового пользователя |
| `3` | Снова показать ранее созданные профили |
| `0` | Выйти |

Для первой установки выберите `1`: укажите IPv4 России, TCP-порт, SNI, вставьте целиком ссылку Армении и задайте имя первого пользователя латиницей. Установщик проверяет конфиг командой Xray `run -test`, а связь с Арменией — реальным VLESS/REALITY-запросом через временный SOCKS-прокси к `https://api.ipify.org`. Ошибка авторизации, firewall или недоступность этого контрольного сайта останавливает установку до применения российских конфигов. Выводится фактический IPv4 выхода в Армении.

Откройте выбранный TCP-порт России для своих клиентов. Полученную российскую `vless://`-ссылку импортируйте в приложение. На устройстве включите глобальный/полный режим туннелирования без локального обхода российских сайтов: решение о стране выхода принимает сервер.

## Добавление пользователей в дальнейшем

```bash
bash /opt/vless-ru/install_ru.sh
```

Выберите `2`, введите уникальное имя и скопируйте новую ссылку. Настройки Армении и существующие UUID сохраняются. Применение конфигурации кратковременно перезапускает Xray и обрывает текущие соединения; приложение сможет подключиться заново. Пункт `3` только повторно печатает и сохраняет профили.

Если вход выполнен обычным пользователем и доступен `sudo`, используйте `sudo bash ...`. Сам установщик требует root; наличие `sudo` в чистом Debian не предполагается. Справка `bash install_ru.sh --help` доступна без root и без изменений системы.

## Что создаётся и как работает

- Автоматически устанавливаются недостающие `python3`, `curl`, CA-сертификаты, `util-linux`, Docker CE и Compose v2 из официального репозитория Docker. Существующие конфликтующие пакеты автоматически не удаляются.
- Установка хранится в `/opt/vless-arm` или `/opt/vless-ru`: `compose.yaml`, `state.json`, `runtime/config.json`, `clients/`, `backups/` и копия установщика. Каталоги доступны только root, секретные файлы имеют права `600`; копия установщика — `700`.
- Используется официальный Xray `26.11.9`; после скачивания в Compose закрепляется фактический digest образа. Контейнер работает с host network, read-only rootfs, `no-new-privileges` и только capability `NET_BIND_SERVICE`.
- Россия выпускает адреса `geoip:ru` напрямую, остальные — через Армению. Прямой выход дополнительно ограничен российскими IP. Автоматического запасного выхода зарубежного трафика через Россию нет. Приватные назначения блокируются.
- Для DNS сначала используется Yandex DoH с проверкой российских ответов, затем Cloudflare DoH через Армению. Начальная конфигурация разрешает домены в IPv4; явно переданные IPv6 обрабатываются по GeoIP при доступной IPv6-связности.
- База GeoIP берётся из закреплённого образа и автоматически не обновляется. Страна определяется по IP, а не языку сайта или окончанию `.ru`.
- Клиентские JSON поднимают локальный SOCKS на `127.0.0.1:10808`, а не системный TUN. Обычные Vision-ссылки по умолчанию не пропускают UDP/443 (QUIC); браузеры обычно переходят на TCP. Остальной UDP передаётся внутри TCP-транспорта.
- Панели управления, квот, срока действия и пользовательской статистики здесь нет. Ссылки и JSON содержат секреты; передавайте каждому пользователю только его профиль.

## Диагностика и восстановление

На нужном VPS (`ru` замените на `arm` для Армении):

```bash
docker compose --project-directory /opt/vless-ru -p vless-ru -f /opt/vless-ru/compose.yaml ps
docker compose --project-directory /opt/vless-ru -p vless-ru -f /opt/vless-ru/compose.yaml logs --tail 100
```

Перед изменением создаётся журнал `pending`; после успеха он становится датированным каталогом в `backups/`. Ошибка применения вызывает откат; незавершённое изменение восстанавливается при следующем запуске установщика. Не удаляйте `pending` вручную. В снимке предыдущие файлы называются `state.json`, `compose.yaml`, `runtime__config.json`; первый снимок новой установки может быть пустым. Для ручного восстановления остановите сервис, восстановите все три файла из одного непустого снимка (последний — как `runtime/config.json`) с правами `600`, затем запустите пункт `1` и повторно получите профили через пункт `3`. Это также возвращает прежний список пользователей.

Сохраните резервную копию всего каталога `/opt/vless-*` вне VPS. Не редактируйте отдельно runtime JSON: при следующем применении он будет сформирован из `state.json`.

## Проверки разработки

```bash
python3 build_installers.py
python3 build_installers.py --check
python3 -m unittest discover -s tests -v
```

При подготовке пройдены 37 тестов с подменённым Docker и реальная проверка синтаксиса Compose (`docker compose config --quiet`). Живой Docker daemon в среде подготовки недоступен: развёртывание на VPS и реальный `Xray run -test` здесь не выполнялись. Сам установщик выполняет проверки Xray и связи с Арменией на целевом VPS. После установки проверьте выход через собственное приложение: зарубежный контрольный сайт должен видеть армянский IP; российский выход проверяйте на известном российском IP или контролируемом сервере, а не только по имени домена.
