# Локальный MQTT: общий режим охраны и iButton

Этот канал существует только между локальным хабом и PLC. Облачный сервер
не подписывается на него. Серийники ключей остаются в конфигурации соответствующего
PLC; прибор сам проверяет ключ и подавляет дребезг/удержание до отправки события.

| Направление | Тема                                           | Содержимое                        |
| ----------- | ---------------------------------------------- | --------------------------------- |
| Хаб → PLC   | `fcplcn/<deviceId>/controllers/security/hub`   | Короткая сессия управления        |
| PLC → хаб   | `fcplcn/<deviceId>/controllers/security/event` | Авторизованное физическое касание |
| Хаб → PLC   | `fcplcn/<deviceId>/controllers/security/set`   | Явное состояние с барьером сессии |

Все три сообщения — **QoS 0, retain=false**. Команды и события не сохраняются
для доставки после восстановления связи. Подписка на события использует MQTT 5
`RAP=true, RH=2`: старые retained-пакеты не принимаются, включая публикации с retain
на уже существующую подписку.

Хаб обновляет сессию примерно раз в секунду. Пример сообщения:

```json
{
  "schemaVersion": 1,
  "bootId": "plc-boot-id",
  "hubEpoch": "hub-process-id",
  "leaseSequence": 18,
  "modeRevision": 4,
  "expiresAtUptimeMs": 124000,
  "touchArmed": false,
  "busy": false
}
```

Срок сессии — **4 секунды** от консервативной оценки текущего uptime PLC.
`hubEpoch` меняется при новом процессе координатора, `leaseSequence` возрастает
без повторного использования после переподключения брокера. `modeRevision` —
сохранённая версия общего намерения; ноль допустим до первого общего сценария.
Во время команды конкретному PLC обновление его сессии приостанавливается,
чтобы очередной импульс не заменил барьер до подтверждения SET.

При свежей сессии разрешённое касание задаёт локально именно `touchArmed`,
после чего PLC отправляет событие:

```json
{
  "schemaVersion": 1,
  "bootId": "plc-boot-id",
  "hubEpoch": "hub-process-id",
  "leaseSequence": 18,
  "modeRevision": 4,
  "eventSequence": 7,
  "eventAtUptimeMs": 121000,
  "value": false,
  "keyId": "key-1",
  "keyName": "Ключ дома",
  "localApplied": true
}
```

Событие допускается только для текущей загрузки PLC, недавно выданной сессии,
актуальной версии и ожидаемого значения. Повторный `eventSequence`, другое
устройство/сессия, устаревшее время или retained отвергаются. События старше
**1500 мс** не переносятся в новую сессию. `localApplied=false` сообщает отказ
локальной операции: намерение всё равно может быть применено к другим PLC,
а источник покажет свой результат отдельно. При `busy=true` касание потребляется
один раз без изменения режима и без постановки в очередь.

Общий координатор сохраняет последнее желаемое состояние. Возвратившийся PLC
сначала должен передать свежие данные своей текущей загрузки; затем получает
**новую** сессию и новый явный SET для актуального состояния. Это не повтор
старой команды из очереди. Дополнительные действия сценария, включая контактор,
запускаются независимо от ожидания подтверждений других PLC.

SET содержит прежние поля `bootId`, `id`, `value`, `sequence`,
`expiresAtUptimeMs` и три поля барьера: `hubEpoch`, `modeRevision`,
`leaseSequence`. Они передаются вместе и должны точно совпадать со свежей
сессией PLC. Срок SET не выходит за её пределы. Прежние локальные ручные SET
без этих трёх полей остаются совместимыми.

Если сессия отсутствует или истекла, физический ключ действует только локально;
никакой отложенный общий сценарий из этого касания после reconnect не запускается.
Охрана и другая автономная логика продолжают работать в C++ на PLC.

## Права брокера

`setup-broker.sh` добавляет отдельные права:

```text
pattern write fcplcn/%u/controllers/security/event
pattern read fcplcn/%u/controllers/security/hub

user fcplcn-hub
topic read fcplcn/+/controllers/security/event
topic write fcplcn/+/controllers/security/hub
```

Имя MQTT-пользователя PLC должно совпадать с его `deviceId`. Поэтому PLC
не может отправить касание от имени другого устройства или получить его сессию.
Имя учётной записи хаба подставляется из `FCPLCN_HUB_MQTT_USERNAME`.
При обновлении существующего развёртывания повторите подготовку ACL брокера
с прежними учётными данными и перезапустите брокер. Исходная команда описана
в `hub/README.md`, раздел Linux / Docker Compose. Смена ACL не требует очистки
пользователей, данных PLC или конфигурации хаба.
