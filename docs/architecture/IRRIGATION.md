# Полив по расписанию

Одно правило задаёт один сеанс полива в каждый из выбранных дней недели.
Например, правило «Грядки утром» открывает кран по понедельникам, средам и
пятницам в 07:00 на 15 минут. Для вечернего полива можно добавить второе
правило с тем же краном и баком. На одном PLC помещается до 16 правил.

## Настройка

1. Откройте раздел «Полив» в веб-интерфейсе PLC или через «Настроить PLC» на хабе.
   Включите модуль, добавьте правило и укажите имя и реле поливочного крана.
2. Для полива по таймеру оставьте в поле бака **«Без бака»**.
   Для полива из ёмкости настройте её в разделе «Баки» на PLC, к которому
   подключены датчики, и включите мониторинг. В правиле выберите бак из списка.
   Хаб добавляет в список баки с других PLC. Например, на контроллере участка
   можно выбрать «Бак с водой · Котельная». Реле крана полива остаётся на PLC,
   где настроено правило.
3. Отметьте дни недели, укажите время старта по местным часам PLC и длительность
   от 1 до 1440 минут. Сохраните настройки и включите правило.
4. На пульте откройте «Полив». Каждому правилу соответствует отдельная плитка.
   Переключатель разрешает или приостанавливает расписание. При отключении
   выполняющегося правила его полив завершается.

Правила для одного реле должны использовать один источник воды. Выберите во всех
правилах этого крана один и тот же бак или везде укажите «Без бака».

## Когда открывается и закрывается кран

| Событие | Действие PLC |
| --- | --- |
| Наступило время старта, выбрано «Без бака» | PLC открывает кран на заданное время. Уровень воды в баках на это правило не влияет. |
| Наступило время старта, мониторинг выбранного бака включён и нижний датчик в воде | PLC открывает кран и отсчитывает заданную длительность. |
| Время истекло | PLC заканчивает этот сеанс. Если другое правило для того же крана продолжает полив, кран остаётся открытым до окончания последнего сеанса. |
| Нижний датчик стал сухим, показания потеряли достоверность или мониторинг выключен | PLC прерывает полив из этого бака и закрывает его поливочные краны. |
| Вода вернулась | Правило ждёт следующего старта по расписанию. |
| Бак подключён к другому PLC, и его показания перестали приходить | PLC закрывает кран. Привязка к баку сохраняется. |
| Хаб, брокер или локальная сеть недоступны | Полив с местным баком или без бака продолжает работать на PLC. Поливу с удалённым баком нужны свежие данные от хаба. |
| Облако недоступно | Связь с удалённым баком работает внутри домашней сети через хаб. |
| PLC перезагрузился | Кран начинает с закрытого состояния. PLC ждёт следующего старта по местным часам. Для правила с баком нужны свежие показания уровня. |

Часовой пояс выбирается в системных настройках PLC. Для Новосибирска значение
`UTC-7` означает UTC+7. В симуляторе поддерживаются фиксированные смещения,
включая получасовые. Если симулятор не распознал пояс, полив останется выключенным
до установки поддерживаемого значения.

## Бак на другом контроллере

PLC с баком передаёт хабу состояние нижнего датчика. Хаб пересылает перечень
баков и свежие показания тому PLC, где настроено правило. Этот PLC проверяет
возраст показания и сам управляет реле и таймером. В каталоге помещается до 96
удалённых баков. Хаб в первую очередь передаёт баки, выбранные в правилах этого PLC.
Если связь восстановилась
после остановки, правило ждёт следующего старта по расписанию.

Для связи нужны хаб и прошивки обоих PLC с поддержкой обмена показаниями для
полива. При ручной установке Mosquitto добавьте права на темы полива по шаблону
в [setup-broker.sh](../../hub/deploy/setup-broker.sh). Установщик хаба обновляет
ACL штатным способом.

## Настройки и состояние

Веб PLC и удалённый редактор читают и сохраняют расписание через
`/controllers/irrigation`. Поля правила — `id`, `name`, `relayId`, `tankId`,
`days` (1 — понедельник, 7 — воскресенье), `startTime` в формате `HH:mm` и
`durationMinutes`. Индивидуальное разрешение меняется командой
`POST /controllers/irrigation/enabled` с полями `id` и `value`.

Хаб получает подтверждённое состояние по MQTT. Поле `actual` показывает работу
этого правила, `valveActual` — подтверждение включения реле крана,
`waterAvailable` — наличие воды по данным бака, `remainingSeconds` — остаток
сеанса. В режиме «Без бака» PLC возвращает `tankId: ""` и `waterAvailable: null`.
При выбранном баке `waterAvailable: null` означает, что уровень неизвестен и полив заблокирован.
Для местного бака `tankId` содержит ID бака. Для бака на другом PLC формат
`<deviceId>/<tankId>`, например `fcplcn-aabb00112233/tank-water`.
Ответ редактора включает доступный каталог `remoteTanks`, где у каждой записи
есть `id`, `name`, `deviceName` и `waterAvailable`.

Расписание и разрешения входят в переносимую резервную копию версии 10.
При импорте старой копии список правил полива пуст. Выполнявшийся сеанс на
восстановленном PLC заново запускается только по очередному расписанию.
