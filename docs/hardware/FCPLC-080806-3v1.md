# FCPLC-080806-3v1

Профиль тестового контроллера предыдущего поколения для прошивки **FCPLCn — Future City PLC Next**.
Технический идентификатор: **`fcplc-080806-3v1`**. Распиновка сверена с пятью листами
`Schematic_FCPLC-3v1_2026-11-21.pdf`; исправление подключения EEPROM согласовано отдельно.
Исправленная [PDF-схема и описание правок](https://github.com/LittleBuster/fcplcn-boards/tree/main/FCPLC-080806-3v1)
находятся в репозитории плат.

## Состав платы

| Узел                      | Исполнение                                         |
| ------------------------- | -------------------------------------------------- |
| Процессор U2              | ESP32-S3-WROOM-1U-N16R8, Flash 16 МиБ, PSRAM 8 МиБ |
| Расширитель U1            | MCP23017T-E/SO, адрес `0x20`, 8 реле и 8 входов    |
| Память состояний U42      | EEPROM **24LC512-I/SM**, адрес `0x50`, **64 КиБ**  |
| Часы U26                  | DS3231MZ+, адрес `0x68`, батарейка CR1220          |
| Внутренняя I²C            | SDA GPIO2, SCL GPIO1                               |
| Внешняя изолированная I²C | SDA GPIO6, SCL GPIO7, подтяжки к `3.3V_iso`        |
| Датчики                   | 6 универсальных линий и 2 отдельных OneWire-линии  |
| Сеть                      | Wi-Fi ESP32-S3                                     |
| Сервис                    | USB Serial/JTAG GPIO19/20, кнопки BOOT и RESET     |

В этой схеме нет W5500 и трансивера RS-485. UART1 выведен как логический последовательный
интерфейс. Линии SD-карты, UART1 и LM75AD (`0x48`) показаны в диагностической карте;
регистрация выводов сама по себе не добавляет драйверы этих устройств.

## Обязательное исправление EEPROM

На первом листе PDF у U42 перепутаны обозначения SDA и SCL. Рабочее подключение:

| Вывод 24LC512       | Подключение               |
| ------------------- | ------------------------- |
| 1, 2, 3: A0, A1, A2 | GND, адрес `0x50`         |
| 4: VSS              | GND                       |
| **5: SDA**          | **I2C1_SDA, GPIO2**       |
| **6: SCL**          | **I2C1_SCL, GPIO1**       |
| **7: WP**           | **GND**, запись разрешена |
| 8: VCC              | +3,3 В                    |

EEPROM, MCP23017 и RTC используют одну внутреннюю I²C с этой распиновкой. В PDF WP отмечен
неподключённым; для тестовой платы его следует соединить с GND. Профиль рассчитан на
исправленное подключение EEPROM.

## Выбор профиля

Для первого запуска этой платы используйте сборку с начальным аппаратным профилем
`fcplc-080806-3v1`: безопасные уровни GPIO должны соответствовать физической плате уже при
загрузке, до инициализации периферии.

Из корня репозитория:

```sh
FCPLCN_BOARD_PROFILE=fcplc-080806-3v1 tools/firmware/build-base
```

Каталог сборки — `~/esp/build/fcplcn/base-fcplc-080806-3v1/`. Готовые образы и контрольные
суммы — `firmware/base/dist/fcplc-080806-3v1/`. В комплект включён `firmware-profile.json`
с исходным профилем образа; упаковщик проверяет его соответствие сборке. Для первичной
USB-прошивки используется `FCPLCn-full.bin`, для обновления приложения — `FCPLCn.bin`.

Обычная команда `tools/firmware/build-base` сохраняет начальный профиль
`fcplcn-161608-1v0` и прежние каталоги `~/esp/build/fcplcn/base/`, `firmware/base/dist/`.
Каталоги можно явно переопределить через `FCPLCN_BASE_BUILD_DIR` и `FCPLCN_BASE_DIST_DIR`;
разные модели следует складывать отдельно. Пакет в каталоге другого профиля не перезаписывается.

Начальный профиль применяется к устройству без сохранённого аппаратного профиля.
Ранее сохранённая валидная модель имеет приоритет при обновлении прошивки. Сначала
прошивка читает настройки и выбирает плату, затем задаёт безопасные уровни её GPIO.
Если настройки нельзя проверить, она входит в восстановление без запуска аппаратных драйверов.

В сервисном веб-интерфейсе откройте **«Система» → модель платы**, выберите
**FCPLC-080806-3v1** и нажмите **«Сохранить и перезагрузить»**. Список моделей загружается
из реестра прошивки. Сохранение задаёт профиль следующей загрузки; текущие выводы и
драйверы продолжают работать с уже активированным профилем до перезапуска.

Настройки отдельных программных контроллеров привязаны к идентификатору платы. При смене
модели проверьте назначения реле, входов и датчиков по таблицам ниже.

## Реле и дискретные входы

U1 имеет A0/A1/A2 на GND. Маска выходов MCP23017 — `0x80FE`, маска входов — `0x7F01`.
Нумерация реле отличается от FCPLCN-161608-1v0:

| Канал | Реле             | Вход            |
| ----- | ---------------- | --------------- |
| 1     | `rly-0/1` → GPA7 | `in-0/1` → GPB0 |
| 2     | `rly-0/2` → GPA6 | `in-0/2` → GPB1 |
| 3     | `rly-0/3` → GPA5 | `in-0/3` → GPB2 |
| 4     | `rly-0/4` → GPA4 | `in-0/4` → GPB3 |
| 5     | `rly-0/5` → GPA3 | `in-0/5` → GPB4 |
| 6     | `rly-0/6` → GPA2 | `in-0/6` → GPB5 |
| 7     | `rly-0/7` → GPA1 | `in-0/7` → GPB6 |
| 8     | `rly-0/8` → GPB7 | `in-0/8` → GPA0 |

Реле активны при HIGH: MCP → ULN2804 → катушка 12 В. RESET# расширителя соединён с +3,3 В;
отдельного GPIO сброса MCP на этой плате нет.

Из-за этого прошивка не может аппаратно удерживать MCP в RESET или гарантировать выключение
уже включённого реле при полностью неработающей I²C. После успешной инициализации I²C она
задаёт и проверяет выключенное состояние выходов. Для испытаний, где требуется независимое
снятие питания нагрузки при отказе связи, нужен отдельный аппаратный способ отключения.

У входов TLP281-4 открытый коллектор без внешних подтяжек на стороне MCP. Поэтому профиль
включает внутренние подтяжки **только на входных битах**, `GPPU = 0x7F01`. У новой платы
FRAM остаётся её собственная политика с отключёнными GPPU.

Сухой контакт на GND шунтирует светодиод входного оптрона. Электрические уровни:

| Сухой контакт  | Вход MCP23017 |
| -------------- | ------------- |
| Замкнут на GND | **HIGH**      |
| Разомкнут      | **LOW**       |

Это обратная полярность относительно FCPLCN-161608-1v0. В аппаратной диагностике
HIGH/LOW показывают электрический уровень; признак активного контакта берётся из профиля.

## Датчики и дополнительные GPIO

Все восемь доступных линий датчиков проходят через ADUM1250 и работают с открытым стоком.
Питание и подтяжки полевой стороны — `3.3V_iso`, земля — `GND_iso`.

| Имя в прошивке | Сигнал схемы                      | GPIO |
| -------------- | --------------------------------- | ---- |
| `sens-0/1`     | SENSOR_1                          | 15   |
| `sens-0/2`     | SENSOR_2                          | 16   |
| `sens-0/3`     | SENSOR_3                          | 17   |
| `sens-0/4`     | SENSOR_4                          | 18   |
| `sens-0/5`     | SENSOR_5                          | 8    |
| `sens-0/6`     | SENSOR_6                          | 9    |
| `sens-0/7`     | OW_SEC, отдельный OneWire/iButton | 47   |
| `sens-0/8`     | OW_TEMP, отдельный OneWire        | 48   |

Обозначение модели отражает шесть универсальных датчиковых линий. Две отдельные
OneWire-линии также доступны программным контроллерам, поэтому API сообщает восемь портов.

| Назначение                | GPIO / уровень    |
| ------------------------- | ----------------- |
| STATUS через ULN2001      | 39, активный HIGH |
| BUZZER через ULN2001      | 38, активный HIGH |
| UART1 RX / TX             | 4 / 5             |
| SD MOSI / MISO / SCK / CS | 11 / 12 / 13 / 14 |
| USB D− / D+               | 19 / 20           |
| BOOT                      | 0, активный LOW   |

В безопасном старте STATUS и BUZZER удерживаются LOW, SD CS — HIGH, UART TX — HIGH.
PWR-индикатор подключён к питанию. Сигнал USB VBUS в схеме не подключён к процессору.

## Выбор постоянной памяти

Технологию памяти задаёт аппаратный профиль:

| Профиль             | Микросхема    | Тип    | Ёмкость |
| ------------------- | ------------- | ------ | ------- |
| `fcplcn-161608-1v0` | FM24CL64B-GTR | FRAM   | 8 КиБ   |
| `fcplc-080806-3v1`  | 24LC512-I/SM  | EEPROM | 64 КиБ  |

Общий журнал состояний использует выбранный драйвер. EEPROM записывается с учётом
128-байтовых границ страниц и завершения внутреннего цикла программирования. Обмен
разбивается на небольшие транзакции, чтобы I²C оставалась доступна опросу входов и реле.
Для FRAM задержка программирования и ожидание готовности EEPROM не применяются.

В разделе **«Аппаратная»** карточка памяти показывает тип, модель, доступность, ёмкость,
занятое журналом место и ошибку последней операции. Журнал проверяет содержимое и
завершённость записи; неподтверждённые или повреждённые состояния не считаются достоверными.

Для проверки сборки и тестов используйте [инструменты прошивки](../../tools/firmware/README.md).
Начальные профили и неизменность исторического алиаса проверяются командой
`tools/firmware/test-base-board-profiles`.
